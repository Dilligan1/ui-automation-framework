# Известные дефекты и особенности окружения

Разделены намеренно: дефект приложения и особенность браузера требуют разных
решений. Дефект документируется и тест на него помечается карантином; особенность
браузера снимается настройкой драйвера раз и навсегда.

---

## BUG-001 — 500 при одновременном входе одного пользователя

| | |
|---|---|
| **Severity** | Major |
| **Компонент** | Auth (бэкенд) |
| **Найден** | параллельный прогон `pytest -n 3` |
| **Статус** | Открыт |

### Шаги воспроизведения

1. Выполнить два входа одного пользователя одновременно (или в пределах
   одной секунды).

### Фактический результат

Часть запросов отдаёт `HTTP 500`, форма показывает «Login failed»:

```
4 одновременных логина одного пользователя -> [500, 200, 200, 500]
```

В логах бэкенда — `UniqueViolationError: duplicate key value violates unique
constraint "refresh_tokens_token_hash_key"`.

### Причина

JWT содержит `iat`/`exp` с точностью до секунды: два входа в одну секунду дают
побайтово одинаковый refresh-токен, вставка его хэша нарушает UNIQUE, и ошибка
не обрабатывается.

Подробный разбор — в [API-репозитории](../api-automation-framework/docs/known-issues.md).

### Как обходится в тестах

Вход под каждой ролью выполняется **один раз за прогон**: сессия сохраняется в
`storage/<stage>/<role>.json`, а доступ к файлу сериализуется `FileLock`
(см. `pages/common_page/login_page/login_page.py`). Параллельные worker'ы
переиспользуют одну сессию вместо того, чтобы логиниться одновременно.
Побочная выгода — прогон заметно быстрее.

## ENV-001 — Chrome блокирует страницу диалогом «Смените пароль»

**Не дефект приложения.** Пароли seed-пользователей (`alice123`, `bob123` и т.п.)
числятся в публичных утечках, поэтому после отправки формы входа Chrome
показывает собственное модальное окно «Смените пароль».

Коварство в том, что окно рисуется браузером **поверх** страницы: клик теста
формально проходит (Selenium не считает элемент перекрытым), но до приложения
не доходит. Тест падает позже и в другом месте — на «меню не раскрылось» или
«счётчик не изменился», — и причина по симптому не читается.

### Решение

В опциях драйвера (`fixtures/ui_fixtures.py`):

```python
options.add_argument("--disable-features=PasswordLeakDetection,AutofillServerCommunication")
options.add_experimental_option("prefs", {
    "credentials_enable_service": False,
    "profile.password_manager_enabled": False,
    "profile.password_manager_leak_detection": False,
})
```

После этого сквозной сценарий стал не только стабильным, но и вчетверо
быстрее: тест больше не ждал таймаутов на перехваченных кликах.
